# LinkLab 快速上手

[返回首页](../README.md) · [下载安装](https://linklab.ineedfull.com/downloads/) · [开发指南](development.md)

本指南按当前仓库源码整理。官网安装包可能早于源码修复；请在「关于」核对版本及构建信息，具体下载文件的发布日期以下载页为准。

目标：在同一台电脑创建 WebSocket 服务端和客户端，完成双向收发。不需要串口设备、云账号或额外服务。

## 1. 选择桌面版

从下载页按系统、CPU 架构和 Electron / Tauri 选择安装包，两端共用工作台。Electron 自带 Chromium，通常占用更多磁盘和内存。下载页与[打包说明](desktop-packaging.md)分别记录现有文件、签名及实机验证范围。

浏览器预览用于查看界面；下面的监听和连接操作需要真实桌面运行时。

## 2. 创建并打开服务端

在端点列表新建端点，填写：

| 参数 | 示例 |
| --- | --- |
| 名称 | 本机 WS 服务端 |
| 传输类型 | WebSocket 服务端 |
| 监听地址 | `127.0.0.1` |
| 监听端口 | `19090` |
| WebSocket 路径 | `/demo` |
| 子协议 | 留空 |
| 默认消息类型 | 文本 |
| Ping/Pong 心跳 | 首次练习关闭 |

点击「保存端点」，再打开该端点，确认进入监听状态。若端口被占用，换一个空闲端口，并同步修改下面的客户端 URL。

## 3. 创建并打开客户端

再建一个端点，名称为「本机 WS 客户端」，传输类型选择「WebSocket 客户端」，URL 填 `ws://127.0.0.1:19090/demo`。

子协议、请求头留空，默认消息类型选文本，自动重连和心跳先关闭。保存后打开客户端；服务端应出现一个远端连接。

## 4. 完成双向收发

1. 选择客户端，发送区选 Text，输入 `hello LinkLab` 并发送。服务端实时消息中应出现这段文字。
2. 选择服务端，发送目标选「全部远端」，输入 `hello client` 并发送。客户端应收到回复。也可以改为「选择远端」后勾选刚连接的客户端。
3. 客户端将发送格式改为 HEX，并将消息类型明确选为二进制，发送 `01 03 00 FF`。服务端应收到 BIN 消息，按 HEX 查看时为这四个字节。
4. 关闭客户端，确认服务端继续监听；重新打开客户端后，再发送一条消息验证恢复。

服务端不会自动回显业务消息，需要手动发送回复。Text / JSON 发送文本，HEX 可发送原始二进制；实际消息类型与字节以消息详情为准。完整规则见[WebSocket 工作台](websocket-workbench.md)。

## 5. 接下来按现场选择协议

| 目标 | 入口与准备 |
| --- | --- |
| TCP / UDP 联调 | 新建对应客户端和服务端；TCP 是字节流，按真实设备约定配置接收分帧，不将一次接收当成一帧 |
| Modbus 采集与模拟 | 新建 TCP/RTU 主站及从站；核对单元地址、功能码、寄存器地址与字序；[自动变化](modbus-simulation.md)可模拟动态数据 |
| OPC UA | [客户端](opcua-workbench.md)负责发现、读写和订阅；[模拟服务端](opcua-simulator.md)提供测试节点 |
| STOMP 消息订阅 | [STOMP 工作台](stomp-workbench.md)，核对 WebSocket URL、destination 与 ACK 模式 |
| 编码与 CRC 校验 | 左下角「工具箱」→ [编码与校验](industrial-toolbox.md)，无需连接设备 |
| 重复验收 | 工具箱中的[设备模板](device-templates.md)与[验收检查](acceptance-checks.md)，保存模型和只读检查证据 |

## 6. 遇到问题先查这里

| 现象 | 检查方法 |
| --- | --- |
| 服务端无法打开 | 查看日志，确认监听地址属于本机、端口未被占用 |
| 客户端握手失败 | 先打开服务端；两边端口、路径和子协议需匹配；本例使用 `ws` |
| 服务端发送无效果 | 确认客户端仍在线，发送模式为全部远端，或已勾选目标远端 |
| 二进制显示为乱码 | 先按 HEX 查看；无法解码的 UTF-8 字节不代表数据损坏 |
| 串口找不到或无法打开 | 检查设备、驱动、系统权限及是否被其他程序占用；本机 WS 示例不需要串口 |
| 有进程却没有窗口 | 记录版本、运行时、关闭/最小化前操作与发生时间，再反馈；不要先删除用户数据 |

反馈入口：[GitHub Issues](https://github.com/ineedfull/ineed-linklab/issues) · [Gitee Issues](https://gitee.com/ineedfull/ineed-linklab/issues)。附应用版本、系统/架构、Electron/Tauri、协议及角色、最小复现步骤和脱敏报文；窗口问题说明进程是否仍在。请求头、证书私钥和客户数据不要公开；安全问题见[安全报告](../SECURITY.md)。
