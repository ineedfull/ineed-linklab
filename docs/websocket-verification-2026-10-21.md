# WebSocket 本机验收（2026-10-21）

本轮在原工作目录增加 WebSocket 客户端/本地服务端，起始提交 `0d111b6`。保留先前 OPC UA 和其他未提交工作，不改应用标识、既有数据路径和历史迁移文件。验收目标均为回环地址，桌面使用隔离配置。

## 范围与修复

两端原生支持 ws/wss 客户端、ws 服务端、文本/二进制消息、子协议、临时认证头、心跳、客户端重连、多人选择/广播/断开；复用共享端点及消息工作台。追加006迁移并验证旧端点和子表保留。

独立审查和协议测试发现并处理以下边界：

- 远端关闭原因可能只回显 Authorization 的令牌片段，逐值替换不足以保护。带请求头或任意非空查询参数的客户端连接，整段远端原因隐藏，保留关闭码。
- 慢速不完整握手会不断刷新 socket 空闲期限，改为从连接开始计算绝对15秒期限。
- 选择的某个客户端已失效时不应中止健康目标发送，两端统一逐目标结果。
- SDK 已开始发送1007/1009协议关闭码时，立即强制销毁会变成1006；Electron 保留其关闭握手并设置有界强制回收。
- Rust 同时启用两个 crypto provider 时存在初始化冲突，WebSocket 的 rustls 配置显式使用局部 ring provider，不修改 OPC UA 的 provider；系统根证书配置按进程缓存。
- Rust 排队发送不能在调用者收到超时失败后才发送，使用入队时的绝对期限，写入前检查期限和应答接收方是否仍存在，过期项不再发送。
- 新 native 模块接入后更新 Electron 边界测试依赖替身；数据库敏感字段源码检查只排除明确的测试模块，继续覆盖完整生产代码。
