# 可重复只读验收检查

本功能用于设备联调后重复核对数值并保存依据。它在 Electron、Tauri 中
使用同一套方案、执行逻辑和界面。首批支持 Modbus 主站和 OPC UA 客户端。

## 使用流程

1. 在端点列表添加并连接 Modbus 主站或 OPC UA 客户端。
2. 打开侧栏底部“工具箱 → 验收检查”，新建方案，选择协议并填写检查项。
3. 为每项指定读取位置和期望值，保存方案。
4. 选择当前已连接的同协议端点，执行检查；需要中止时点击停止。
5. 查看本次报告，再次执行或导出 JSON/Markdown，交给同事复核。

验收检查不会自动连接设备、扫描网络或写入数值。OPC UA 模拟服务端和
Modbus 从站可用于准备测试数据，验收方案绑定到读取它们的客户端/主站。

## 读什么、如何判断

Modbus 只允许 FC1/2/3/4，地址从 **0** 开始；实际值是 Boolean 或整数数组。
例如读取两个保持寄存器，严格相等的期望 JSON 是 `[321,654]`，不是
`"321,654"`。读取单个数值时也可选择数字闭区间判断。

OPC UA 通过当前会话重新读取 NodeId，使用本次响应中的值和质量，
不把订阅表格里的旧值当成本次结果。质量不是 Good、节点不存在、
读取失败或会话变化都不能通过。Int64/UInt64 仍使用十进制字符串，
避免 JavaScript Number 丢失精度；期望 JSON 也需要带引号。

严格相等区分数值、字符串、Boolean、null、数组和对象；数字范围只接受
有限数值，不把字符串或 Boolean 自动转换为数字。范围包含上下界。

## 停止与报告

每次执行固定方案快照和目标会话。修改方案后，旧报告仍保留当时的条件。
普通断言失败可以继续后续检查；断连、删除、会话变化或停止会中止后续项。
未执行项有独立状态，不能算通过。

停止后，正在处理的原生读取可能还需要结束；在此期间不能启动第二轮。
迟到的响应不能将已停止报告改成通过。关闭验收面板可以继续使用工作台，
执行状态与报告仍由主工作台持有。

JSON 报告用于机器读取与复核，Markdown 用于阅读和项目交接。
报告包含方案、目标身份、会话、起止时间、实际值、质量、读取证据和错误。
报告证明的是一次读取与比较的结果，不能代替完整设备认证或现场验收签字。

## 保存与交接文件

方案和报告保存在原有本地 SQLite 工作区设置中，沿用原数据目录。
可通过设置中的工作区导出/导入一起交接；单个方案也可导出 JSON 并在
另一工作区导入。导入先校验完整文件，生成新方案 ID，不覆盖已有方案。
方案不携带连接密码；接收方需要自行选择已连接端点。

方案 JSON 和报告 JSON 使用紧凑格式，避免缩进使有效数据超过导入或导出上限。
Markdown 保留可读标题与时间，每项证据使用一行完整 JSON；其中换行按 JSON
规则转义，反引号保持原值，不会提前结束代码围栏。所有格式都保留完整数据。

最多保存 50 个方案，每方案 25 项，单方案 64 KiB。最多保留 20 份报告，
单份 512 KiB，总文档 2 MiB；达到总量时优先清理最旧报告。需要长期归档的
报告应及时导出。过大的实际值应明确报错，不能截断数据后判断通过。
保存失败会保留当前草稿和未保存报告；修复存储问题后重试保存。

内部数据使用毫秒时间戳，界面与 Markdown 使用本地
`YYYY-MM-DD HH:mm:ss.SSS`，与其它 Tool 一致。

## 维护入口

设计与实现计划见 `docs/superpowers/specs/2026-10-24-acceptance-checks.md`
及 `docs/superpowers/plans/2026-10-24-acceptance-checks.md`。
执行器和文档校验位于共享 `packages/workbench/src/model/acceptance*.js`；
平台协议通过既有 Modbus 调度器和 OPC UA 原生命令读取。

在源码根目录执行：

```sh
npm run build
node tooling/acceptance-test/desktop-acceptance.mjs electron
node tooling/acceptance-test/desktop-acceptance.mjs tauri
```

脚本加载构建后的共享界面，启动品牌宿主、独立 localhost Modbus TCP peer
与 Node OPC UA fixture，通过实际表单建立方案并调用真实原生协议。
Electron 使用临时 userData，Tauri 使用临时测试应用 identifier；产品的应用 ID
与用户数据目录不变。结果目录打印为 `out`，保留 `result.json`、原生数据目录
位置 `isolation.json`、独立磁盘核对 `sqlite-verification.json`，失败时保留
`failure.json`；Electron 另有截图与导出文件，Tauri 有原生启动日志。

2026-10-24 本机 Electron、Tauri 原生流程均通过：各保存 3 个方案、5 份报告
（通过、失败、通过、失败、停止），各产生 3 次真实 Modbus FC3 读取，未发送写请求。
两端 SQLite 独立只读核对均与 renderer 重载结果完全一致。Electron 的 JSON/
Markdown 导出文件亦通过内容核对。证据目录：

- Electron：`/var/folders/1p/8trwjmld3q131crnsq356t_80000gn/T/linklab-acceptance-electron-Xe0CJX`
- Tauri：`/var/folders/1p/8trwjmld3q131crnsq356t_80000gn/T/linklab-acceptance-tauri-9lxS1Z`

这里的重载是 renderer 重新加载；未将完整退出应用后再次启动列为本次原生验收。

Tauri 脚本通过本地宿主 HTTP 响应控制测试等待，避免验收脚本依赖 WebView
计时推进；原生网络读取、停止和迟到结果仍使用产品真实行为。最终计时探针显示
100ms renderer 计时器在 253ms 宿主等待内触发。此前两轮停滞和一次 WebKit
下拉框 `innerText` 选择器失败均保留为失败证据；本轮没有修复或宣称定位产品
计时器缺陷。`progress.jsonl` 与 `result.json.timerDiagnostics` 可用于后续诊断。

原生流程核对 Modbus 成功/不匹配、修改草稿后旧报告快照不变、OPC UA
Double/Int64/UInt64、未知节点失败、慢响应中停止及未执行项、迟到结果不改写
停止报告、renderer 重载，以及隔离 SQLite 与重载结果完全一致。
Electron 导出运行完整 IPC/exporter/文件写入链路，测试只替换保存对话框的
目的地选择；这不等于人工点击过系统保存面板。Tauri 的系统保存对话框未自动化，
导出边界及过滤器由原生测试覆盖，真实对话框交互仍需人工验收。

本机原生验证针对 macOS arm64 开发宿主和 localhost；不代表 Windows/Linux
安装包、远程设备、Modbus 实体 RTU 或长期现场运行验收。浏览器主题/字号/
侧栏/窄窗口矩阵使用协议 fixture，应与原生协议结果分别记录。运行后关闭的
仅为脚本自身宿主与 fixture；隔离 SQLite 和失败证据保留供复核。

## Engineering values from device models

Saved schemes generated by **设备模板** carry the executed point decoding and
model revision snapshot. Their actual value is the engineering scalar, while
result evidence retains the raw Modbus response, transport and decoding quality,
unit and configuration. Raw Modbus array checks and OPC UA checks retain their
existing formats. Engineering range boundaries may use exact decimal strings;
Boolean/text points use equality. See [device templates](device-templates.md)
for extraction, new instance creation, revision behavior and native verification.
