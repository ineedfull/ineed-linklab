# 工业数据工具箱：范围、必要性与使用约定

日期：2026-10-16。状态：首批九类工具已实现，本机验收及剩余平台检查见文末。此文同时是完整候选能力清单和首版设计依据。

## 是否有必要

建议增加一个随 LinkLab 提供的离线工具箱。现有协议工作台能处理通信中的特定数据，但现场工程师仍有“尚未连设备，先核对手册示例”“收到未知字节，试读不同类型”“确认校验范围与发送字节顺序”等任务。独立入口可以减少复制到网页或另一软件的步骤，并让算法、位宽、编码规则可见。

必要性依据分三层：

1. 本项目事实：`packages/codecs/src/payloadCodec.js` 已有 UTF-8 文本与 HEX 解析；`dlt645.js` 已有协议专用 BCD、地址及加减 33H；`packages/workbench/src/model/modbusDataOrder.js` 已有字节/字顺序配置，`modbusCommands.js` 已有 RTU CRC 展示与计算。这些分散在通信流程中，没有独立转换面板。新增价值来自离线解释、比对和校验入口。
2. 技术与同类产品证据：CRC 目录为常见算法提供参数及标准检查值；RFC 20 明确 ASCII 是 7 位编码；RealTerm 官方页列出 HEX、8/16/32 位、大小端、有/无符号和浮点显示。这说明这些任务与通信调试相邻，但不证明我们用户的实际使用频次。
3. 当前限制：本轮没有用户访谈、现场时间测量或安装量统计。“高频”是基于现有协议与现场流程的优先级判断。发布后应观察是否能独立完成下面的任务，再决定后续投入；不以工具数量作为成功标准。

首版验收任务：用 Modbus 示例核对 CRC 及低字节先行；识别 4 字节浮点的交换顺序；解释 64 位寄存器值而不丢精度；保留设备编号 BCD 的前导零；看清串口 ASCII 的 CR/LF/NUL；返回原通信界面后保留端点、发送草稿和后台连接。

## 实现选择

比较三种方式：只保留协议内转换，界面增加最少但无法独立使用；单独新应用，分发和维护成本高且打断通信流程；随 LinkLab 提供独立面板，能离线使用、保留工作台上下文且双运行时共用。选择第三种。

侧栏底部“工具箱 → 编码与校验”打开带焦点约束的面板，按“编码转换 / 数值与字节 / 校验计算”分组。每项工具有说明、示例、输入、显式参数、计算、结果和复制。关闭或切换工具保留本次会话草稿；修改输入或参数后立即清除旧结果，避免误复制旧值。关闭应用后不保存报文；不增加数据库或权限。

计算为共享 JS 纯函数，工具目录与表单状态在共享 workbench 中，平台入口只挂同一个组件。既有 HEX 解析规则继续复用并转换为中文错误。通用 BCD 用十进制字符串保留精度和前导零，不能直接套用 DL/T 645 专用有符号/浮点舍入逻辑。既有 Modbus 协议计算本轮不改，使用已知帧向量交叉核验新 CRC。

## 首版行为约束

- 输入上限 65,536 字符，字节计算最多 16,384 字节；超过上限拒绝，不能截断后计算。BCD 最多 128 个十进制数字，小数位 0–12。CRC 只在点击计算时执行。
- HEX 接受连续或按完整字节用空白分隔的格式。拒绝半字节、非法字符；不自动删除 `0x`、逗号等可能误解的内容。表单明确提示支持格式。
- 整数使用 BigInt 与固定宽度校验，不使用 Number 承载 64 位整数。非十进制进制转换按所选位宽的补码解释；十进制输入表示实际数值，禁止溢出取模。
- 浮点用 DataView；32 位舍入在结果中显示实际编码值；有限输入溢出为 Infinity 时拒绝。解码 NaN/Infinity、负零可见；不把 IEEE 浮点近似当成精确十进制。
- 32 位顺序明确显示 ABCD/BADC/CDAB/DCBA；64 位用“每 16 位字交换字节 / 反转 16 位字顺序 / 整体反转”描述，避免误用四字母。变换按完整 16 位字处理，奇数字节交换报错。
- ASCII 只接受 U+0000–U+007F；非 ASCII 字符/字节拒绝。控制字符转义显示；不把中文默默编码成 UTF-8。
- 压缩 BCD 每个半字节必须为 0–9；不处理符号位。编码数字位数为奇数时左补 0 并说明；解码保留前导零。小数位显式配置，超出精度拒绝而非舍入。
- CRC 标明 width/poly/init/refin/refout/xorout，算法名不使用含糊的“CRC16”；数值结果与高/低字节序列分别展示。Modbus 默认低字节先行，其它算法通过显式顺序选择。
- SUM16 定义为输入各字节累加后模 65536，不能等同于 16 位字求和；LRC 为逐字节和的 8 位二补码，XOR8 只代表该异或算法。校验值单独输入，数据输入不包含尾部校验。没有待核对值时只算数值，不显示“校验通过”；不匹配给出明确失败状态。
- 工具箱只作本地计算和主动复制，不发送报文、不改变通信参数、不增加网络请求。剪贴板不可用或失败时保留可选中的结果并显示失败原因；异步复制的旧完成不能覆盖新工具状态。
- 浅/深色、普通/大字、侧栏展开/折叠、窄窗口、键盘导航均要验证。纯计算双端相同，浏览器验证与真实桌面验证分别记录。

## 使用入口与示例

1. 点击侧栏底部“工具箱 → 编码与校验”，默认打开“校验计算 / CRC 校验”。尚未创建或连接端点也可以使用。
2. 点击“载入示例”，输入为 `01 03 00 00 00 0A`；点击“计算”，CRC 数值为 `CDC5`，Modbus 低字节先行的发送字节为 `C5 CD`。
3. 在“待核对校验字节”填入 `C5 CD` 后再计算会显示通过；填 `CD C5` 会显示不匹配。这里输入的是字节序列，数据栏不要再次追加 CRC。
4. 按分类选择其它工具，核对方向、位宽、符号及字节顺序后计算。“载入示例”按当前参数生成数据，保留转换方向、进制、位宽、符号、字节顺序和校验算法；例如 HEX 解码得到字节示例，BCD 随小数位生成数据。位域示例同时替换为当前位宽的掩码；已填写的待核对校验字节会替换为匹配示例的值，留空则仍只计算。Modbus CRC 使用 RTU 请求，其它 CRC 使用 ASCII `123456789` 的 HEX 标准测试向量。载入后清除旧结果，点击“计算”查看；切换工具和关闭面板保留已有草稿与结果。无效参数仍会提示错误，不会自动恢复默认值。
5. 点击对应结果的复制按钮；剪贴板失败时仍可选中结果手动复制。Escape 关闭面板并返回入口焦点，原连接和发送草稿继续保留。

例如压缩 BCD 输入 `0012.34`、小数位 2、高位数字字节先行，得到 `00 12 34`；UInt64 输入 `18446744073709551615` 得到 8 个 `FF`；Float32 输入 `1`、整体反转得到 `00 00 80 3F`。按设备手册选择参数，不能仅凭字节外观推断编码。
