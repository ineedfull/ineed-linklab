# Modbus device templates and engineering acceptance

Approved scope: reusable Modbus TCP/RTU master model templates, stored revisions, explicit import preview/export, new endpoint instantiation and fresh readonly engineering checks. Existing send templates, raw Modbus/OPC UA schemes and reports remain compatible.

Templates contain an ID, model name, monotonic revision, safe request groups and point decoding configuration, plus readonly acceptance conditions bound to group/request/point IDs. Extraction strips field connection addresses and all unknown configuration fields. Imported models are strictly validated and bounded. Export never includes passwords, host or serial device. A new revision appends to the library and never modifies a previous revision. The bounded library (50 revisions, 256 KiB each, 2 MiB document total) lives in the optional `templates` member of the existing version 1 acceptance document; old three-member documents stay valid and native hosts accept the optional member.

The shared DeviceTemplatesPanel offers extract/update, JSON preview with model/point/check counts, explicit save import, export, and TCP/RTU instance fields (name, actual host/port or serial path/baud/parity, unit ID). The instantiated endpoint receives newly generated identity, safe configuration with automatic polling disabled and unit IDs replaced in every group. It cannot overwrite a previous endpoint. Users explicitly open it afterward. Acceptance conditions are editable as bounded JSON with a documented structure; templates initially derive range conditions from configured point minimum/maximum when both are present. Users can add equality or range conditions for any enabled point.

Generate an ordinary saved acceptance scheme for an instance or run it directly through the existing runner. Each engineering check snapshots point configuration and template identity/version and reads fresh raw data through the existing scheduler. `decodeModbusMasterPoint` determines value/quality; no last-good cache is used. Good transport quality and good decode quality are both required. Exact 64-bit integers retain string values; range comparisons use exact decimal fractions and unsafe scaled integers remain uncertain and fail. Raw words, native evidence, point decoding, unit, model/version and quality are included in report evidence. Imported passed engineering reports must reproduce the decoded value from their raw evidence. Reports and template revisions are immutable.

No private-frame parser, anomaly scenarios, OPC UA model templates, publishing or commits are included. Tests use isolated memory/SQLite and loopback only. Shared renderer UI must fit light/dark, normal/large fonts, collapsed sidebar and narrow windows. Native packaging/other OS acceptance is outside this source change.
